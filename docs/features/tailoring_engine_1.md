# Tailoring Engine Design

## Vision

The Tailoring Engine is **not** a resume rewriter.

Its purpose is to bridge the gap between:

- Resume Analysis
- Career Conversation
- Recruiter Expectations

and ultimately answer one question:

> **"How can we maximize this candidate's chance of getting an interview?"**

---

# Problem Statement

Traditional resume tools optimize for keyword matching.

That is insufficient.

Example:

Resume Match: **85%**

Actual Result:

❌ Resume rejected without interview.

This means keyword overlap alone is not enough.

The Tailoring Engine should optimize for **Recruiter Confidence**, not just keyword similarity.

---

# Inputs

The Tailoring Engine combines information from four sources.

```
Resume
      +
Job Description
      +
Resume Analysis
      +
Career Conversation
```

Each input contributes different information.

## Resume

Candidate's current resume.

Contains:

- experience
- projects
- education
- skills
- summary

---

## Job Description

Target role requirements.

Contains:

- required skills
- preferred skills
- responsibilities
- seniority expectations

---

## Resume Analysis

Generated by Resume Analysis workflow.

Includes:

- strengths
- weaknesses
- category scores
- missing skills
- recruiter observations

---

## Career Conversation

The most valuable source.

During the conversation the candidate often reveals information that never appeared on the resume.

Examples:

- "I still code every day."
- "I built ResumePilotAI."
- "I mentor junior engineers."
- "I wrote Python automation scripts."
- "I worked on performance optimization."

This becomes **Recovered Evidence**.

---

# Tailoring Pipeline

```
Resume
      +
JD
      +
Resume Analysis
      +
Career Conversation
      ↓

Recovered Evidence
      ↓

Hiring Reality Check
      ↓

Gap Classification
      ↓

Resume Tailoring
      ↓

Recruiter Review
      ↓

Final Resume
```

---

# Step 1 — Recovered Evidence

Convert conversation into structured evidence.

Example

Original Resume

```
Worked with founders.
```

Conversation

```
I designed and implemented ResumePilotAI
using FastAPI, Python, Gemini and React.
```

Recovered Evidence

```
Designed and implemented an AI-powered
resume analysis platform using FastAPI,
Python, Gemini, OpenRouter and React.
```

Recovered evidence becomes eligible for inclusion in the tailored resume.

---

# Step 2 — Hiring Reality Check

Instead of only reporting a Match Score, estimate the likelihood of getting shortlisted.

Example

```
Technical Fit
92%

Recruiter Confidence
54%

Interview Probability
Moderate
```

This reflects reality better than a single percentage.

---

# Step 3 — Gap Classification

Not all gaps are equal.

Classify every gap into one of three buckets.

---

## Can Improve

Candidate can realistically improve this before applying.

Examples

- Better summary
- Better project descriptions
- Quantified impact
- GitHub projects
- Python project
- React project
- Architecture diagrams
- Resume formatting

---

## Can Explain

Candidate has experience but failed to communicate it.

Examples

- Performance optimization
- Mentoring
- Product ownership
- CI/CD ownership
- Design documents
- Technical leadership

These become:

- Resume improvements
- Interview talking points

---

## Cannot Fix Quickly

Candidate cannot realistically acquire this before applying.

Examples

- 10 years Kubernetes
- Azure production ownership
- Managed 40 engineers
- Staff Engineer experience
- Security clearance

Instead of asking users to "improve" these,

the Tailoring Engine should say:

> This role may not be a good fit today.

This prevents users from wasting time applying for impossible roles.

---

# Step 4 — Resume Tailoring

Rewrite the resume using:

- JD
- Resume Analysis
- Recovered Evidence

Possible improvements:

- better summary
- reordered experience
- stronger bullet points
- stronger technical emphasis
- quantified impact
- clearer ownership
- highlight relevant projects

Nothing should be fabricated.

Only:

- existing resume content
- recovered conversation evidence

may be used.

---

# Step 5 — Recruiter Review

Final validation pass.

Prompt:

> Pretend you are the hiring manager for this role.

Evaluate the tailored resume.

Answer:

- Would you shortlist?
- Why?
- What still concerns you?
- What would make this candidate stronger?

This gives candidates the feedback recruiters rarely provide.

---

# Final Report

Instead of one "Resume Match" number, present a richer report.

Example

| Metric | Meaning |
|----------|---------|
| Technical Fit | Skill overlap with JD |
| Recruiter Confidence | Likelihood of shortlisting |
| Resume Clarity | How easy the story is to understand |
| Evidence Strength | How well claims are supported |
| Missing Requirements | Hard blockers still remaining |

---

# Guiding Principles

## Never fabricate experience

Only use:

- resume
- projects
- career conversation
- analysis

---

## Be recruiter-realistic

If recruiters would reject,

say so.

Do not inflate scores to make users feel better.

---

## Prefer actionable advice

Every recommendation should answer:

> What can the candidate actually do next?

---

## Distinguish between

- Things to improve
- Things to explain
- Things impossible to change quickly
